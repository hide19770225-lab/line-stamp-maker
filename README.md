# STAMP atelier — LINEスタンプ制作ツール

10個のキャラクターが **2列×5段** に並んだ画像を1〜4枚読み込み、分割・背景透過・日本語の文字入れ・PNG/ZIP保存を行う静的Webアプリです。まず1枚で10個をテストでき、4枚を加工すると40個のスタンプ＋メイン画像＋タブ画像の計42画像を書き出せます。

**追加料金・APIキー・会員登録は不要。** HTML/CSS/JavaScriptだけで動作し、有料API、画像生成AI、CDN、外部フォント、解析サービス、外部ライブラリは使いません。画像・セリフはサーバーへ送信せず、Canvasで端末内処理します。CSPでも通信処理（`connect-src`）を禁止しています。サイト表示時にはHTMLなどの静的ファイルを取得します。

## 使い方（iPhone Safari対応UI）

1. **画像を読み込む**：「画像を選択する」からPNG/JPEG/WebPを1枚選びます。「サンプル画像で試す」なら画像なしでも、白いうさぎ10個で試せます。元画像は合計4枚まで。1ファイル40MBまで、読み込み後は長辺2560px以内に縮小してメモリを抑えます。HEICはPNG/JPEGに変換してから選んでください。
2. **分割を調整する**：緑の縦線・横線をドラッグするか、数値（%）で調整します。外周3本の縦線・6本の横線を動かせるため、画像外側の余白も除けます。スタンプの順番は各元画像の左上→右上→次段、元画像の読み込み順です。
3. **背景を透過する**：「四隅から自動判定」「白」「色を選ぶ」「透過しない」を選びます。許容差を調整し、「10個に分割して、透過を確認」を押します。設定は元画像ごとに保持します。設定変更後は、その元画像を再加工してください。
4. **白い部分を確認する**：一覧の画像をタップ。チェック柄・濃い色・ピンク背景で確認します。自動透過は端につながる近い色だけを取り除き、輪郭に囲まれた白は残します。ただし、輪郭の切れ目や白い背景につながった白い体は誤透過する場合があります。「元の色を戻す」「消す」ブラシでなぞって修正できます。「1つ戻す」（最大8操作）と「自動透過に戻す」も利用できます。穴の中に残った背景もブラシで消せます。
5. **セリフを入力する**：個別編集、または一覧下の「セリフをまとめて入力する」で1行1個、最大40行を入力します。最大120文字/個。空欄は文字なしです。一括反映は既存セリフを上書きし、未入力行は空欄にします。入力先は加工済みスタンプのみなので、40行を入れるときは先に4枚を加工してください。
6. **文字を整える**：ゴシック/明朝/丸ゴシック、サイズ、上下左右の位置、文字色、白ふちを調整します。日本語は端末の日本語フォントを使います。iPhoneではヒラギノ系が使われ、丸ゴシックがない端末はゴシックへ切り替わります。長い文字は自動改行します。枠を超える場合は検査で保存を止めるため、サイズや位置を修正してください。「文字の見た目を全スタンプに適用」でまとめて揃えられます。
7. **透過の確認を記録する**：各画像の「白い部分と透過の仕上がりを確認した」にチェックして「確認して次へ」。40個の申請用ZIPは全画像の確認後に保存できます。手動で透過を修正すると確認状態は解除されます。
8. **10個でテストする**：1枚だけ加工した状態でも、`line-stamps-test-10.zip`（スタンプ10個＋メイン＋タブの12画像）を保存できます。テスト用は未確認でも保存可能です。10/20/30個のZIPは、このツールの40個セットの申請用ではありません。
9. **40個を仕上げる**：残りの画像を読み込み、それぞれ分割・透過・確認。1枚ずつ追加しても、ほかの元画像の編集は残ります。再分割時は対象の元画像の10個だけセリフ・透過修正をリセットします（事前確認あり）。
10. **ZIPを保存する**：メイン用・タブ用のスタンプをそれぞれ選び、申請前チェックを確認。「申請用ZIPを作成して保存」から `line-stamps-40.zip` を保存します。自動保存が始まらない場合は、処理後の「作成したZIPを保存する」をタップ。iPhoneではSafariのダウンロード一覧、または「ファイル」アプリのダウンロード先を確認してください。1個だけのPNG保存も編集画面からできます。

**編集中の画像やセリフは自動保存されません。** 再読み込み・タブ終了・iOSによるタブの破棄で消えます。完成後は必ずZIPを保存してください。iPhoneはメモリが限られるので、ほかの重いタブを閉じて1枚ずつ加工することをおすすめします。

## 出力と自動検査

| ファイル           | サイズ    | 備考                                           |
| ------------------ | --------- | ---------------------------------------------- |
| `01.png`〜`40.png` | 370×320px | 元画像の縦横比を維持して配置・日本語文字を合成 |
| `main.png`         | 240×240px | 選択スタンプの透明部分を除いた内容を中央に配置 |
| `tab.png`          | 96×74px   | 選択スタンプの透明部分を除いた内容を中央に配置 |

すべて透過RGBA PNG、偶数寸法、外周10pxの透明余白付きです。スタンプのキャラクターは最大350×250pxに配置し、下側に文字用の空間を設けています。自動検査は40個の揃い、透過確認状態、空画像、文字のはみ出し、分割/透過設定変更の未反映を確認します。保存時に実際のPNGが各1MB以下であることと、ZIPが20MB以下であることを検査します。20MBはこのアプリの保守的な安全上限です。ZIPは互換性の高い非圧縮形式（PNG自体は圧縮済み）で、独自のCRC32チェック付きです。

**自動検査だけでLINEの申請・審査通過を保証できません。** 白い部分の保護、切れたキャラクター、文字の読みやすさ、著作権・肖像権、表現・販売条件、最新の規定は人が確認してください。とくに小さいタブ画像のセリフは読みにくくなるため、文字なしのスタンプを選ぶと見やすくなります。申請は[LINE Creators Market](https://creator.line.me/ja/)で別途行ってください。[公式制作ガイドライン](https://creator.line.me/ja/guideline/sticker/)も確認してください。このツールはLINEの公式サービスではありません。

## GitHub Pagesで無料公開

`index.html` はリポジトリのルートにあります。ビルドやバックエンドは不要です。

1. この変更をGitHubの `main` ブランチへコミット・プッシュします。
2. リポジトリの **Settings → Pages → Build and deployment** を開きます。
3. **Source: Deploy from a branch**、**Branch: main**、**Folder: / (root)** を選び **Save**。
4. デプロイ後、GitHub Pagesに表示されたURLをiPhoneのSafariで開きます。標準URLは `https://hide19770225-lab.github.io/line-stamp-maker/` です（公開完了を意味するものではありません）。

GitHub FreeでPagesを無料公開するには、通常は公開リポジトリを利用します。非公開の場合はプランのPages利用条件を確認してください。API課金やサーバー費用はありません。公開操作はこのコード作成には含めていません。

## ローカルで開発する

Python 3がある場合：

```sh
cd /workspace/line-stamp-maker  # チェックアウトしたディレクトリ
python3 -m http.server 4173 --bind 127.0.0.1
```

手元のPCではブラウザで `http://127.0.0.1:4173` を開きます。Node.jsやnpmはアプリの実行には不要です。各ファイルは相対パス参照なので、GitHub Pagesのプロジェクト配下でも動作します。

## テスト

Node.js 18以上で、追加依存なしのアルゴリズムテスト：

```sh
node --test tests/core.test.cjs
```

白い内部の保持、背景色/許容差、元のアルファ値、透明領域、CRC32/ZIPヘッダーを検証します。

ブラウザ統合テスト（開発時のみPlaywrightが必要。アプリの依存には含みません）：

```sh
npm install --prefix /tmp/stamp-browser-tests --cache /tmp/stamp-npm-cache --no-audit --no-fund --package-lock=false playwright
# 別のターミナルで上記Pythonサーバーを起動してから実行
NODE_PATH=/tmp/stamp-browser-tests/node_modules node tests/browser.cjs
python3 tests/verify_zip.py /tmp/stamp-test-artifacts
```

既定のブラウザは `/usr/bin/chromium`。必要なら `CHROMIUM_PATH`、`STAMP_TEST_URL`、`STAMP_TEST_ARTIFACTS` で変更できます。テスト画像・スクリーンショット・ZIPは `/tmp/stamp-test-artifacts` に保存されます。

統合テストはiPhone 13相当の画面・タッチ設定で、実PNG読み込み、10→40個の加工、分割線、透過修正/元に戻す、日本語セリフ、文字はみ出し検査、40個の透過確認、12/42画像のZIPダウンロード、外部通信なし、横スクロールなし（390px/320px）を検証します。Pythonの標準ライブラリでZIPを展開し、全PNGの実寸法・透明余白・非空・サイズ・CRCも検証できます。

**実機iPhone Safariでは未検証です。** この開発環境ではWebKitのダウンロード先が通信制限で拒否されたため、Chromiumでの画面エミュレーションまでを実施しています。GitHub Pages公開後、実機Safariで画像選択・ブラシ操作・日本語フォント・ZIP保存を確認してください。推奨はiOS 16以降のSafariです。

## ファイル構成

- `index.html`：日本語UI、GitHub Pages公開ルート
- `styles.css`：レスポンシブ表示、タッチ操作、大きな操作ボタン
- `core.js`：端からのフラッドフィル透過、Canvas描画、文字入れ、PNG、ZIP
- `app.js`：画像読み込み、分割調整、透過修正、確認・検査・ダウンロード
- `tests/`：アルゴリズム・ブラウザ統合・生成ZIPの検証
