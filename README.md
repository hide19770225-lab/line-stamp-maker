# STAMP atelier — LINEスタンプ制作ツール

画像の分割・背景透過・日本語の文字入れ・個別編集をブラウザだけで行い、**8・16・24・32・40個**のLINEスタンプとメイン／タブ画像をZIP保存する無料の静的Webアプリです。従来の2列×5段の10個入り画像と、10個のテストZIPにも対応しています。

**追加料金・有料API・APIキー・会員登録は不要です。** HTML/CSS/JavaScriptのみで動きます。画像生成AI、バックエンド、CDN、外部フォント、解析サービス、実行時の外部ライブラリは使いません。画像とセリフは端末内で処理し、外部へ送信しません。CSPでも`connect-src 'none'`を指定しています。サイトを開くときには静的ファイルだけを取得します。

## 基本の使い方

1. **制作セットを決める**：「申請するスタンプ数」で8・16・24・32・40個を選びます。初期値は従来互換の40個です。枚数を減らすと範囲外のコマを除外しますが、セリフと個別設定は40番まで残ります。増やした後は「空き番号を順に割り当てる」や手動割り当てで追加してください。
2. **セリフを先に登録する**：「セリフを先に登録・まとめて編集する」に1行1個、最大40行、各120文字以内で入力し「セリフを登録する」を押します。画像を読み込む前でも登録・JSON保存が可能です。空行は文字なし。登録は40番までを上書きし、未入力の行は空欄にします。「番号ごとのセリフを確認・修正」から個別に直すこともできます。
3. **画像をまとめて読み込む**：「新しい画像の初期配置」を選び、PNG/JPEG/WebPを選択します。複数ファイルの一括選択・ドラッグ＆ドロップに対応。選択した順序（ファイル選択画面が返す順序）で元画像を並べます。最大40ファイル、各40MB、読み込み後は長辺2560px以下に縮小し、保持する元画像の合計は3200万画素以下に制限します。HEICはPNG/JPEGに変換してください。
4. **画像ごとに配置を設定する**：元画像を選び、「この画像の配置」で2列×5段、5列×2段、4列×2段、2列×4段、4列×3段、5列×8段、1列×1段を選択できます。列数・行数は手動でも指定できます（各1〜40、合計160コマ以内、1コマ最低2px）。画像ごとに別の配置を使えます。サンプル画像は常に2列×5段です。
5. **分割と採用コマを調整する**：緑の線をドラッグ、または数値（%）で位置を微調整します。外周も動かせます。「各コマの端を切り抜く」で四辺を0〜20%内側へ動かすと、背景透過の前に隣の罫線を除けます。オレンジの破線が実際の範囲です。
6. **番号と画像を対応させる**：「コマの採用・番号を調整する」で各コマの出力番号を指定。「除外」は処理・出力しません。番号には登録したセリフも表示します。使用中の番号を選ぶと、元の番号と交換します。「除外コマに空き番号を順に割り当てる」は、左上から右、上から下へ空き番号を割り当てます。
7. **加工する**：背景色を「四隅から自動判定」「白」「色を選ぶ」「透過しない」から選び、許容差を調整します。現在の画像だけ、または「読み込み済みの画像をまとめて加工」で全画像を加工。まとめて加工は変更のある採用画像だけを処理します。割り当ては全画像を通して最大40個です。
8. **個別に仕上げる**：一覧の画像をタップして、サイズ・位置・透過修正・文字を調整します。セリフは番号順に自動で紐付き、一覧にファイル名とセリフを表示します。画像とセリフの組み合わせ、誤字、白い部分の透過を確認してください。
9. **確認して保存する**：「白い部分と透過の仕上がりを確認した」にチェックして「確認して次へ」。メイン画像とタブ画像の番号をそれぞれ選び、ZIPを保存します。選択した番号が全て揃い、透過の確認が済むと申請用ZIPになります。

### 番号・ファイル名・セリフがずれない仕組み

セリフと加工設定は**01〜40の固定番号**に保存します。元画像は読み込み順、各画像のコマは**左上から右、上の段から下**の順です。最初は空いている番号を自動で割り当て、選択枚数を超えるコマは除外します。配置の形を変えても、同じコマ順の番号は維持します。増えたコマには空き番号を割り当てます。

たとえば02番のコマを除外しても、03番は`03.png`と03番のセリフのままで、02番に繰り上げません。別のコマに02番を割り当てて欠番を埋めてください。01番と03番のコマを交換すると、画像の割り当てが入れ替わり、01番のセリフは01番に残ります。手動割り当て・配置変更後は影響のある元画像を再加工します。未反映の設定があるとZIP保存を止めます。

画像をどの順に加工しても、一覧とZIPは**出力番号の昇順**になります。セリフを後から変更しても、番号以外で推測して画像に紐付けることはありません。

## 文字デザイン自動作成

新しく登録したセリフは、初期状態でデザインの自動提案・自動配置が有効です。画像加工前にセリフを登録しても、後から個別編集で入れても、完成プレビューとPNG／ZIPに合成されます。

- **6種類のプリセット**：元気（オレンジ・大きめ・斜め）、ポップ（紫系・丸ゴシック）、かわいい（ピンク・丸ゴシック）、やさしい（緑・控えめな影）、強調（赤・太い白フチ）、シンプル（落ち着いた色・影なし）。日本語のフォントは端末のヒラギノ等を使います。
- **セリフから自動提案**：「ありがとう」「おやすみ」はやさしい、「やった」「！」は元気、「だいすき♡」はかわいい、などの言葉を端末内のルールで判定します。選択したプリセットを指定することもでき、色・サイズ等の個別修正は優先して残ります。外部APIは使いません。
- **調整**：文字色、白フチON/OFFと太さ0〜12px、影0〜12、サイズ14〜64px、角度−30〜30°、フォント、上下左右の希望位置を個別に設定できます。
- **重なりを避ける自動配置**：文字の白フチ・影とキャラクターの透明度を実際に調べ、不透明な領域の周囲に間隔を残して配置します。空きがなければ、縦横比を保ったキャラクターの表示を自動で縮小・移動して余白を確保します。元画像・消しゴム修正・画像配置の元設定は書き換えません。文字を消すと元の画像配置に戻ります。
- **長いセリフ**：自動改行し、必要なら文字を14pxまで小さくします。収まらない場合は警告して出力を止めるので、セリフを短くしてください。自動縮小の有無と実際の文字サイズは編集画面に表示します。
- **iPhoneでドラッグ**：プレビューの文字を直接なぞるか、「文字を移動」を選び、ドラッグして動かします。消しゴムとは別の操作で、画像の透明度は変わりません。自動配置ONでは、希望位置の近くで重なりを避けるよう補正します。位置のスライダーでも調整できます。
- **40個へ一括適用**：制作セットの「文字デザインをまとめて作成」で全40番号に適用できます。「セリフから自動提案」を選べば各セリフの提案が使われます。編集画面の「文字の見た目を全スタンプに適用」は、その個別調整もまとめて適用します。どちらも確認後に個別設定を上書きするため、残したい設定は先にJSON保存してください。セリフ自体と画像加工の設定は残ります。

一括適用後も各画像で個別修正でき、デザイン・影・角度・自動配置の指定もJSON保存／復元します。以前のJSONに文字デザインの指定がない場合は、従来の手動配置・色・フォントを維持します。「カスタム（従来の設定）」や自動配置OFFでは手動位置を使い、重なりがあれば警告します。自動配置ONのまま重なりが残る場合はPNG／ZIP出力を止めます。最終一覧・比較画面で、読みやすさや顔が隠れていないかを確認してください。

## 個別編集（既存機能）

- **大きさ・位置**：透明な余白を除いて最大350×300pxに配置。初期90%、20〜100%のスライダーと拡大・縮小ボタンを使えます。縦横比と外周10pxの余白を維持します。左右・上下は残りの余白内で移動するため、100%で動けない方向は少し縮小してください。「大きく中央に配置する」で戻せます。
- **切り抜き**：「このスタンプの切り抜き範囲」で四辺を0〜40%内側へ調整。消しゴム修正・セリフは保持し、範囲を戻すこともできます。
- **透過・消しゴム**：端につながる近い色だけを透過し、輪郭に囲まれた白は残します。輪郭の切れ目や背景とつながる白い体は誤透過することがあります。チェック柄・濃い色・ピンクで確認し、「消しゴム」「元の色を戻す」で修正。「1つ戻す」（最大8操作）、「やり直す」、「自動透過に戻す」も使用できます。太さはプレビュー上のpx。拡大・移動後も表示位置に追従します。輪郭の端を消した後は残った内容に表示サイズを合わせ直します。
- **編集前後の比較**：元画像のコマ（共通切り抜き後、背景あり）と、文字を含む現在の仕上がりを並べて確認します。iPhone相当の縦長画面では編集プレビューが上部に固定されます。
- **日本語文字**：ゴシック／明朝／丸ゴシック、14〜64px、上下左右の位置、文字色、白ふちを個別調整。「文字の見た目を全スタンプに適用」も利用できます。日本語は端末のフォントを使い、対応しない丸ゴシックは代替のゴシックに切り替わります。長い文字は自動改行します。画像と重なる場合は画像か文字を移動・縮小してください。

再加工しても、番号ごとのセリフ・文字・画像の配置・個別切り抜き設定は維持します。消しゴムの修正は**同じ元画像・分割位置・採用番号・背景設定**の場合だけ復元し、条件が変われば初期透過からやり直します。画像の仕上がりを変更したら目視確認をやり直してください。

## セリフ・加工設定をJSONで保存・再開

「セリフ・加工設定をJSON保存」で `stamp-atelier-project.json` を保存し、「設定JSONを読み込む」で復元できます。

保存するもの：

- 選択した制作枚数と、40番までのセリフ・フォント・文字サイズ・位置・色
- 画像ごとの名前・寸法・SHA-256照合値、列数・行数・分割線・共通切り抜き・コマ番号の割り当て・背景透過設定
- 番号ごとの拡大率・位置・個別切り抜き、メイン／タブの選択番号
- 消しゴム／復元による透明度の修正差分（色のデータは含みません）

**元画像・色付きの画像・完成PNGはJSONに含みません。元画像ファイルも手元で保管してください。** JSON読み込み後は元画像一覧の「元画像を再選択」、または画像読み込みから同じファイルを選び直し、加工ボタンを押します。ファイルのSHA-256を端末内で照合し、一致しない画像に保存設定を適用しません。同じ名前だけでは一致扱いにしません。既に同じ画像を読み込んでいる場合は再利用します。サンプルは「サンプル画像で試す」から再読込できます。

画像を生成する前のセリフ・制作枚数だけでもJSON保存できます。一括入力は「セリフを登録する」を押してから保存してください。復元後は透過の目視確認をやり直します。取り消し／やり直しの履歴は保存せず、現在の透明度だけを復元します。設定ファイルは20MBまで、形式・値・番号重複を検査してから読み込み、無効なファイルで現在の制作内容を上書きしません。

作品は自動保存されません。再読み込み、タブ終了、iOSによるタブの破棄で作業中の画像は消えます。途中はJSON、完成後はZIPを保存してください。画像照合にはHTTPS（GitHub Pages）またはローカルサーバーが必要です。

## 上端の白線・孤立した線や点の確認

編集画面の「孤立した線・点を拡大確認する」を開きます。完成PNGと同じ画像をグレー／黒／チェック柄、全体／2／4／8倍で確認でき、拡大時は指で上下左右にスクロールできます。候補横の「拡大」で該当部分へ移動します。枠・番号・確認用背景は出力しません。

候補は文字合成前の前景の連結成分から検出します。**手足・葉っぱ・白い装飾も候補になるため、自動削除しません。** 不要だと確認できたものだけチェックし「選択した候補だけ消す」を押します。「1つ戻す」「やり直す」で取り消し可能です。線が本体につながるなど検出できない部分は既存の切り抜き・消しゴムで修正します。削除内容はPNG／ZIPとJSONの透明度差分にも反映されます。申請前の検査にも孤立候補の番号を表示しますが、正しい装飾を残したまま出力できます。

切り抜いた範囲外の線が拡大補間で復活する問題は、範囲を別Canvasへ切り出してから拡大することで防ぎます。自動透過では、角に透明画素のある透過済み画像の白い本体・装飾を保持します。背景が残るときは「白」などを明示指定し、目視確認してください。[調査・修正前後とテスト範囲](docs/white-residue-investigation.md)も参照してください。実際の不具合ZIPは未入手のため、報告された09.png／10.pngそのものは未検証です。

## 出力と検査

| ファイル                 | 寸法      | 備考                            |
| ------------------------ | --------- | ------------------------------- |
| `01.png`〜選択枚数の番号 | 370×320px | PNG、縦横比維持、透明な余白付き |
| `main.png`               | 240×240px | 選択スタンプの内容を中央に配置  |
| `tab.png`                | 96×74px   | 選択スタンプの内容を中央に配置  |

- 申請用は `line-stamps-8.zip`／`line-stamps-16.zip`／`line-stamps-24.zip`／`line-stamps-32.zip`／`line-stamps-40.zip`。選択枚数＋2画像をZIP直下に保存します。
- まだ揃っていない場合は `line-stamps-test-10.zip` などのテストZIPとして保存できます。テスト用は未確認でも保存できますが、選択したセットの申請用ではありません。欠番はそのままでファイル名を詰めません。メイン・タブには加工済みの番号を選んでください。
- 全画像は透過RGBA PNG、偶数寸法、外周10pxの透明余白付きです。空画像・文字のはみ出し・分割設定の未反映・選択枚数分の番号・透過確認状態を検査します。保存時に実ファイルを各1MB以下、ZIPを20MB以下（このアプリの保守的な上限）と確認します。ZIPは非圧縮形式、PNG自体は圧縮済みでCRC32付きです。
- iPhoneではSafariのダウンロード一覧、または「ファイル」アプリで保存先を確認します。保存が始まらない場合は「作成したZIPを保存する」をタップ。編集画面から1枚だけのPNG保存もできます。

自動検査でLINEの審査通過を保証するものではありません。切れたキャラクター、白い部分、文字の読みやすさ、著作権・肖像権、表現・販売条件と最新規定は人が確認してください。小さいタブ画像は文字なしのスタンプを選ぶと見やすくなります。申請は[LINE Creators Market](https://creator.line.me/ja/)から別途行い、[公式制作ガイドライン](https://creator.line.me/ja/guideline/sticker/)も確認してください。LINEの公式サービスではありません。

## GitHub Pagesで無料公開

`index.html` はリポジトリ直下です。ビルド・バックエンドは不要です。

1. 変更をGitHubの`main`にマージ／プッシュ。
2. **Settings → Pages → Build and deployment → Source: Deploy from a branch** を選択。
3. **Branch: main / Folder: / (root)** で **Save**。
4. デプロイ後、表示されたURLをiPhone Safariで開きます。標準URLは `https://hide19770225-lab.github.io/line-stamp-maker/` です。

GitHub FreeでPagesを無料公開する場合、通常は公開リポジトリを使います。非公開の場合はプランのPages利用条件を確認してください。APIやサーバーへの追加課金はありません。

## 開発・テスト

アプリの実行にNode.js・npmは不要です。Python 3でローカルサーバーを起動できます。

```sh
cd /workspace/line-stamp-maker
python3 -m http.server 4173 --bind 127.0.0.1
```

手元のPCで `http://127.0.0.1:4173` を開きます。相対パス参照なのでGitHub Pagesのプロジェクト配下でも動きます。

Node.js 18以上で、追加依存なしのアルゴリズム／設定管理テスト：

```sh
node --test tests/core.test.cjs tests/project.test.cjs tests/typography.test.cjs tests/residue.test.cjs
```

ブラウザテスト（Playwrightは開発時のみ。実行アプリの依存ではありません）：

```sh
npm install --prefix /tmp/stamp-browser-tests --cache /tmp/stamp-npm-cache --no-audit --no-fund --package-lock=false playwright
# 別ターミナルでPythonサーバーを起動後
NODE_PATH=/tmp/stamp-browser-tests/node_modules node tests/browser.cjs
NODE_PATH=/tmp/stamp-browser-tests/node_modules node tests/project-browser.cjs
NODE_PATH=/tmp/stamp-browser-tests/node_modules node tests/typography-browser.cjs
NODE_PATH=/tmp/stamp-browser-tests/node_modules node tests/residue-browser.cjs
python3 tests/verify_zip.py /tmp/stamp-test-artifacts
python3 tests/verify_typography_zip.py /tmp/stamp-test-artifacts
python3 tests/verify_residue_zip.py /tmp/stamp-test-artifacts
```

既定の実行ブラウザは `/usr/bin/chromium`。`CHROMIUM_PATH`、`STAMP_TEST_URL`、`STAMP_TEST_ARTIFACTS` で変更できます。結果は `/tmp/stamp-test-artifacts` に保存します。

既存の10／40個の加工、白い内部の保持、個別配置・切り抜き、タッチ消しゴム・取り消し・やり直し、日本語文字・比較・メイン／タブ・ZIPの回帰検証に加えて、8／16／24／32／40個の実ZIP、複数画像とレイアウトの混在、左上からの順序、除外・番号交換・欠番維持、画像生成前のセリフ登録、JSONからの画像照合と消しゴム修正のピクセル一致、不正JSONの拒否を検証します。Pythonの標準ライブラリで全PNGの寸法・余白・非空・サイズ・CRCと、出力画像の色による番号対応を検査します。

文字デザインの検証では、6プリセット×3角度の実際の文字・白フチ・影と不透明キャラクターのアルファ値を比較して重なりが0であることを確認します。タッチでの文字移動、40番号への適用と個別修正、文字入りZIP内の全PNGに文字色・白フチ・キャラクターが含まれることも検査します。

**実機iPhone Safariは未検証です。** ChromiumのiPhone 13相当の画面・タッチ設定と390px／320px幅で検証しています。WebKitの取得先は開発環境の通信制限で利用できません。推奨はiOS 16以降のSafariで、公開後に実機で画像選択・日本語フォント・ブラシ・JSON／ZIP保存を確認してください。

## ファイル構成

- `index.html`：日本語UI、Pages公開ルート
- `styles.css`：既存デザインとタッチ対応
- `core.js`：画像分割・透過・描画・ブラシ・PNG・ZIP
