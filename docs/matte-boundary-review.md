# 背景透過・境界残留候補の改善

その後の「手動選択なしの自動除去」は[最新の実ZIP検証](automatic-residue-cleanup.md)に記載しています。本書は比較・承認を中心とした前段階の記録です。

## 原因と調査範囲

`core.js`、`residue.js`、`app.js`と既存テストを調査し、変更前に次の3件の失敗を再現しました。

1. 「白／指定色」の背景透過はRGBの近さだけで外周から消しており、背景色に近い**元から半透明の影・装飾**も透明度0にしていた。
2. 不透明なアンチエイリアスの縁は、許容差の外なら完全不透明で残り、許容差の内なら一律で消える。背景色が混じった縁を自然に残す調整段階がなかった。
3. 孤立成分に切り抜き境界からの距離情報がなく、境界の線・小さい番号の残りを見つけにくかった。本体近くの細い動き線も削除可能な候補になり得た。

前回の実画像09.png（左155・上25px、49×1px）／10.png（左177・上10px、16×1px）も再利用して検証しています。これらの線が**元の一覧画像にあったのか、当時の加工工程で生じたのかは未確定**です。工程を特定するには、加工前の10個入り一覧画像と、列・行、分割位置、切り抜き余白、透過モード・許容差などの設定（保存JSONがあればそれ）が必要です。完成PNGから推測して自動削除する変更はしていません。

## 必要最小限の変更

### core.js

- 白・指定色・自動の外周背景除去で、元のアルファ値が1〜254の画素を保護。透明な画素と不透明な背景は従来どおり処理し、閉じた輪郭内の白は保持する。
- `proposeMatteCleanup`を追加。背景除去後の透明領域に2方向以上で接する、元は完全不透明な縁の1層だけが対象。背景色との差が許容差を少し超える画素のアルファ値だけを軽減し、RGBは変更しない。内部へ繰り返し削り込まない。
- **軽減案は自動適用しない**。元から半透明の影・装飾、内部の白、背景と十分異なる輪郭色は変更しない。既に透明な画像の自動モードでは背景色を推定して軽減しない。

白い背景と、輪郭のない白いキャラクターは色だけでは区別できません。背景色が既に混ざった画素の本来の色を復元する処理でもありません。淡い輪郭を誤って薄くする可能性があるため、比較して利用者が承認する方式です。既存のRGB・元画像は保持し、適用は既存のマスク修正として扱います。

### residue.js

- 元画像の切り抜き境界からの最短距離を記録。端から4pxまたは短辺の約2%以内を「境界付近」として表示するための分類を追加。
- 本体の輪郭から数px以内の細い独立成分を、動き線・汗・涙などかもしれない保護候補として扱い、候補削除APIでも拒否。
- ハートなどのまとまった成分、閉じた輪郭内の表情、文字・白フチ・影の完成画素検査に関する既存の保護は維持。
- 形状だけで番号・動き線・煙・装飾の意味を断定しない。細い線や点でも不確実なものは自動削除しない。保護された不要部分は、利用者が既存の切り抜き・消しゴムで修正できる。

分割時は既存の「周囲の切り抜き余白」と、範囲を別Canvasへ物理的に切り出す処理を維持。指定した余白・範囲外の隣コマの線は分割段階で除外できる。元一覧画像がない状態で、境界に触れる本物の手足・葉などを勝手に消す追加の自動フィルターは入れていません。

### app.js / index.html

- 「輪郭の背景色にじみを確認する」に、現在の完成画像と軽減案の比較、適用／キャンセルを追加。比較中のPNG・ZIPは現在の編集結果のまま。編集条件が変わると提案を破棄し、適用は「1つ戻す／やり直す」で取り消せる。
- 一覧の「残留候補のあるスタンプを順番に確認」と、編集画面の「次の候補のあるスタンプへ」を追加。一括削除はせず、画像ごとに確認する。完成PNGだけの候補も既存の完成画素監査を利用して確認対象に含める。
- 候補に境界付近の表示を追加。既存の拡大、黒／グレー背景、前後比較、選択削除、消しゴム、取り消しを維持。
- セリフ・固定番号・配置・JSON形式・ZIP保存形式・画像サイズは変更していない。軽減の適用結果も従来のアルファ差分でJSONに保存できる。

## テスト

変更前に追加した3件のテストが失敗し、実装後は通過しました。

- `tests/core.test.cjs`：元から半透明の影・装飾、閉じた白い内部の保持、提案の非破壊性、RGB不変、適用範囲が縁1層であること。
- `tests/residue.test.cjs`：境界線と小さい番号相当の分類、動き線の保護、検出で元画像が変化しないこと。
- `tests/matte-browser.cjs`：iPhone相当の画面で比較だけでは未適用、キャンセル不変、承認後だけ反映、取り消し・やり直し、10枚を順番に確認して既知の線・番号だけを削除、白い内部とアルファ90の影を保持してZIP出力。
- `tests/verify_matte_zip.py`：実ZIPをPython標準ライブラリで独立復号し、全10枚で一覧との全RGBA一致、余分な線／番号成分がないこと、白い内部・本体色・独立した影の保持、370×320／240×240／96×74px、余白・CRCを検査。
- 以前の全テストも実施。10／40枚、8／16／24／32／40枚、自由分割、セリフ・番号、文字デザインと自動配置、JSON、消しゴム、メイン・タブ、ZIPを回帰検証。実際の09.png・10.pngについても、既知の線だけの削除、装飾保護、一覧・単体PNG・ZIP一致を再検証。
