# かんたん一括制作モード

## 実装

- `index.html` / `styles.css`：通常制作を残し、画像・セリフ読込→自動加工→一覧確認→ZIP保存の4ステップを追加。通常の画像ごとの設定を表示する導線も用意。
- `app.js`：既存の画像読込・番号割当・加工・セリフ登録・一括検査・ZIP出力を呼び出す導線を追加。加工済みで設定未変更の元画像は再加工しない。文字の一括上書きは明示指定時のみ適用し、適用後は上書き指定を解除。個別修正と既存セリフを保持。
- `easy.js`：画像不足・画像重複・番号重複・元画像未選択・4枚制限とセリフ入力を非破壊で検証。
- `tests/easy.test.cjs` / `tests/easy-browser.cjs` / `tests/verify_easy_zip.py`：全5種類の申請枚数、画像の番号順とセリフ、文字一括設定、明示的な目視確認、個別編集後の再確認、JSONと通常モード、PNG／ZIPを検証。

`core.js`、`residue.js`、`typography.js`、`project.js`、`audit.js`のアルゴリズムとJSON形式は変更していません。一括検査を共有関数に抽出し、PR #10の個別編集・目視確認と同じ処理を使います。

## 安全性と操作

新規画像だけ2列×5段で読み込みます。既存の分割線、除外・番号、透過設定、透明度修正、セリフ、画像配置は維持します。新規画像の番号は読み込み順に空き番号へ割り当てる既存処理です。すでに番号を手動変更したプロジェクトは再番号付けしません。

入力を変更したセリフは全40番号へ登録するため、空行や入力のない後続番号は空になります。未入力・未変更なら既存設定を維持します。文字の一括設定を明示しなければ個別の文字設定を変更しません。JSON読込では未反映のかんたんモード入力を破棄してJSONを優先します。

不足や重複などのエラーは加工前に停止します。同一ファイルの重複読み込みは警告し、追加しません。4枚を超える選択は読み込まず元の画像を維持します。対象外コマは未採用数を表示し、元画像を削除・編集しません。

自動加工は既存の安全な透過・限定的な上端残留線除去・文字配置・余白確保を使用します。不確実な残留物は要確認とし、一括検査では削除しません。自動処理では確認済みにしません。エラーがない全画像を利用者が目視した場合だけ一括確認できます。かんたんモードからのZIP保存は全数・目視確認済みが必須です。通常の部分テストZIPは従来どおり利用できます。

## 検証と限界

- Node.js：47件（既存44件＋かんたんモード3件）。
- 新規ブラウザテスト：8・16・24・32・40枚。2列×5段の画像を最大4枚順次読み込み、実際の各コマの色と番号・日本語セリフを比較。文字の一括フォント・サイズ・色、目視前ZIP禁止、確認後の各枚数＋メイン・タブのZIP保存を検証。
- 40枚：個別セリフ・文字サイズ編集、確認解除、再試行時の画素不変、再確認・再出力、JSON保存と再読込、通常モード切替、未反映下書きがJSONを上書きしないこと、4枚制限・重複・入力上限のエラーを検証。
- ZIPはPythonで独立デコードし、各枚数＋個別編集後40枚についてファイル名、寸法、透明余白、容量、PNG／ZIP CRC、全スタンプとメイン・タブのプレビューRGBAハッシュ一致を検証。
- 既存ブラウザ9スイートを回帰検証：通常制作、自由分割・番号・JSON、文字デザイン、自動配置、背景透過、消しゴム、残留候補、Undo/Redo、一括透過確認、実画像の上端残留線自動削除、PNG・ZIP。

検証ブラウザはChromiumのiPhone 13タッチ設定です。実機Safariおよびホーム画面から起動した画面の操作・保存は未確認です。外部通信・有料API・実行時依存は追加していません。GitHub Pagesの静的配置を維持しています。

同一画像の重複検出はファイルのSHA-256による照合です。見た目が同じでも再圧縮・再保存された異なるファイルの重複までは判定しません。OSやブラウザが渡すファイル順が意図どおりか、表示されたファイル名と完成画像・番号を目視してください。
