# 個別境界・描き込み背景の保護（2026-10-23）

## ベースと原因

GitHub連携で最新mainを照合し、PR #106マージ済みのa56c4f7から作業。
Git fetchは環境のproxy接続失敗のため利用できなかったが、GitHub APIのmainコミットSHAとローカルHEADが一致した。

コード上では、列別の行境界が一か所でも不明だと全列の検出結果を破棄していた。
また、描き込み市松模様に単色の背景フラッド除去が適用され得た。
今回の不具合ZIPは未提供のため、25〜35番の現物の原因特定・改善確認とは区別する。

## 変更

- PR #106の列検出・管理番号除去を維持。列別行検出に任意の診断出力を追加し、安全な境界を保持する。
- 不明境界には暫定位置を使ってプレビューを生成するが、接する上下のコマを個別確認対象にする。背景モデルや列が不明な場合は全コマが対象。
- 文字・絵・装飾を色や最大成分だけで切り捨てず、全前景に対する既存の空白検出を維持する。OCRや意味認識を実装したものではない。文字内の空白を段の空白と誤認する可能性は残る。
- 不透明な周辺の周期的な白・灰の交互パターンを検出した場合、背景色フラッドを行わずアルファを保持。透過済みとは扱わない。
- 該当コマは一括検査でエラーにし、個別編集での確認済み操作を必要とする。一括チェックによる未確定箇所のまとめ承認を防ぐ。
- 白背景の除去は既存の外周からの連結フラッドを維持し、閉じた輪郭内の白い顔・体を保護する。
