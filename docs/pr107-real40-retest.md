## 追加修正

- 全画像を貫く縦の空白がない場合、ちょうど8段の水平空白を確認し、各段で個別の列境界を探す。全段で安全な列境界が見つかる場合だけ採用する。原画専用の座標の埋め込みや、文字・小成分の一括削除は行わない。
- 行別の列境界は等分位置に近い空白を優先。39・40番の2pxの空白より広い空白を選ぶと40番のハートが39番へ移るため、このケースを回帰検査へ追加。
- 自動モードで非常に明るい背景を除去するときは許容差を最大8に制限し、輪郭が開いた淡いクリーム色の体を外周フラッドで消さないよう保護。白・カスタムモードや純白の開いた体に対する万能な分離ではない。
- 分割プレビュー・番号位置・切抜座標も行別の境界を使用。手動の列・行変更後は古い自動境界を使わない。自動境界の直接ドラッグは行わず、配置設定から手動調整する案内を表示する。
- 行別自動境界は元画像から再計算する。プロジェクト形式の変更はない。実画像の再加工で40枚のPNG一致を確認したが、今回の実画像について設定JSONを再読込する一連の操作は未検証。

## 残る問題

1. 暗い背景では文字・輪郭の白い縁と、開いた体の下端などの薄い背景残留が見える。保護を弱めて体を再び透過させる変更は採用していない。画素の正しい前景アルファは不透明な原画から一意に得られず、白縁を含むマット調整は残課題。
2. 純白で輪郭が開いた体、背景と同色の文字内空白、変形・不規則な市松模様などの一般的な分離は未解決。今回の画素検査は上記の定義に限り、全ての淡い半透明画素の完全保持を保証しない。
3. 39・40番は2pxの境界を使い、前景近接警告が残る。意味による装飾の自動帰属判断は実装していない。
4. Linux ChromiumのiPhone 13表示設定で検証。実機iPhone Safariは未検証。
