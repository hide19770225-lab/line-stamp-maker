## 調査と根本原因

画像入力（upload-bridge / app）、分割・透過・描画・ZIP（core）、保存設定（project）、日本語合成（typography）、残留線検査（residue / audit）、候補提案（suggestions / caption-vision）、かんたんモード（easy）、画面とCI・既存テストを調査。

- 自動検出した横境界は等間隔の元セルから移動するが、番号検出は切抜画像の左上を基準としていた。実フォントで01〜40を印字した合成テストで2〜8段目の検出失敗を再現。元セルの探索領域を実切抜座標へ変換して修正。
- 暗い画素だけの連結判定は色付きの絵につながる黒い部分を孤立成分と誤認し得た。さらに番号周囲の矩形を消していた。透明度に基づく完全な8近傍成分を調べ、色付き・大きい・単独の成分は除去せず、整列した2成分の画素のみ除去する。
- 配置変更時に以前の列別境界が残っていた。配置変更では境界を初期化。プレビューの番号位置も列別境界へ統一し、横線のドラッグは触った列だけを変更する。
- 分割位置未確定の警告が番号・境界の警告を上書きしていた。警告を併記する。
- iOSの共有API失敗時に同じ共有経路を再試行するしかなかった。通常ダウンロード用の別リンクを設け、共有機能判定・同期例外・非同期失敗にも対応。変更時に両リンクを無効化する。
- 既存単体テスト2件は、40元画像対応と列別境界フィールド追加に期待値が追従していなかった。現仕様に更新し、配置変更・絵の保護の回帰検査を追加。既存ブラウザ検査も推奨モードの変更と明示保存リンクに追従。
