# 一括制作の個別調節と公開ビルド情報

## 変更

- かんたん一括制作でも元画像ごとの分割・切り抜き設定を表示。10個入り元画像の通常制作と同じ画面を使用します。
- 加工後の全スタンプを番号順で表示し、共通の個別編集ダイアログで大きさ・左右上下位置・各辺の切り抜き・10px/20px安全余白を調節します。番号選択・前後移動を追加しました。
- 調節は番号に紐づく独立した `layout`・`crop`・`style.safeMargin` に保存します。他番号へ適用する操作をしない限り、他画像に影響しません。「この画像の調節を保存して一覧へ」で一覧を更新します。保存操作と透過の目視確認は別です。
- ページ内での自動保存に加え、既存の設定JSONで端末への保存・再読込ができます。画像そのものはJSONに含みません。かんたんモードでは「セリフ・設定JSONの保存を表示」で保存ボタンを表示できます。
- 個別プレビュー・一覧・ZIPは引き続き同じ `StampCore.renderStamp` を使用します。調節後は過去のZIPと一括検査を無効化します。
- モバイルの調節用スライダーの高さを44px以上にしました。範囲設定を最初から開き、プレビュー直下に調節項目を配置します。

## バージョンと公開手順

`VERSION` がリリース番号の唯一の設定元です。初回のビルド番号は `1.0.0`。今後はリリース時にこのファイルを更新します。

```sh
DEPLOY_ENVIRONMENT='production (GitHub Pages)' node scripts/build.cjs
```

`dist/` に公開用の静的ファイルを生成します。`build-info.js` / `build-info.json` にはビルド時のバージョン、チェックアウトしたコミットSHA、ビルド日時（UTC ISO）、指定したデプロイ環境、内容のハッシュを記録します。日時はUIでAsia/Tokyoに変換して表示します。コミットは `BUILD_COMMIT`、`GITHUB_SHA`、ローカルgit HEADの順で取得し、不正・取得不能ならnullにします。環境名は明示的なビルド入力がなければnullです。

ソース直接配信ではビルド情報を持たないため `Ver. 不明` と各項目の「不明」を表示します。PRの最新コミットを問い合わせて公開情報に見せかける処理はありません。すべてのJS/CSS URLに同じビルド内容ハッシュを付け、キャッシュの混在を避けます。

`.github/workflows/pages.yml` はmainのpushでテスト→ビルド→GitHub Pagesデプロイを行います。PRブランチで手動実行してもデプロイはスキップし、previewとしてのビルドに留めます。GitHub PagesのSourceが「GitHub Actions」の場合に利用できます。従来の「Deploy from a branch」でルートを直接配信している場合は、このビルド処理が実行されないためビルド情報は不明です。SourceをActionsに設定するか、別の公開パイプラインから `dist/` を配信する必要があります。

**この修正ではPages設定の変更・ワークフロー起動・公開デプロイ・mainへのマージは行いません。PR #67への保存を公開サイトの更新とは扱いません。** 実際の公開確認はデプロイ完了後に公開URLの `build-info.json` と画面情報を照合してください。

バージョンをタップすると、その画面のビルド情報を表示します。`pageshow`・画面への復帰・手動確認では同一オリジンの `build-info.json` だけをno-storeとクエリ付きで取得します。差異があれば再読込を案内し、表示中のバージョンは書き換えません。取得失敗時は「不明」として比較不能を伝えます。再読込はユーザー操作と確認後に限り、設定JSON保存と元画像再選択の案内を表示します。画像の外部送信はありません。CSPのconnect-srcを同一オリジンだけに限定して許可しました。
