# かんたん制作の読込・加工状態と失敗表示

## 確認できた問題と未確定の原因

最新版mainにはPR #12の部分制作対応が含まれており、40個設定・画像1枚でも10個を加工する経路はあります。一方、③の旧メッセージは加工済み画像が0個のときに出るもので、元画像が読み込み済みかを区別していませんでした。加工失敗後に③を押すと直前の具体的な原因も一般的なメッセージで上書きされていました。新しいブラウザテストを修正前に実行し、「画像1枚が読み込み済みなのに未読込を示すメッセージになる」ことを確認しました。

利用者から②の直後に「未割当の番号11〜40」の不足メッセージが出ることも確認しました。旧版の表示・古いJSの混在は可能性の一つですが、実機・実際の表示URLとそのレスポンスを確認できていないため確定していません。今回の修正で、表示版、加工段階、具体的なエラーが残るようにします。iPhone実機固有の停止原因が解決したと断定するものではありません。

## 変更

- `app.js`：読込済み枚数、採用コマ数、加工済み数、申請枚数を別々に表示。加工開始・失敗・完了を管理し、エラーには工程、元画像名、分割中のPNG番号と元の例外メッセージを残す。③を押しても原因を消さない。再試行時は既存の元画像とセリフを利用し、成功時に失敗表示を解除。
- `easy.js` / `app.js`：画面の事前案内と実加工で同じ部分制作の検証を使う。「不足30個でも、読み込み済み10個のテスト加工を続ける」と明示。申請用ZIPと全数一括承認では従来の枚数・目視確認チェックを維持。
- `app.js`：入力イベントの有無だけでなく、入力欄の実際の値と登録済みセリフを比較。ブラウザ等が値だけを復元したケースでもセリフ変更を反映。
- `index.html` / `easy.js` / `app.js`：版 `easy-state-1` を表示し、app.jsとeasy.jsの版が異なる場合は保存・再読込の案内を表示。キャッシュ識別子も更新。自動で再読込したり、画像・入力を削除したりしない。古いHTMLに新しい診断欄がない場合も、必要な欄だけ補完して起動時エラーを防ぐ。
- `styles.css`：消えないエラー欄の表示を追加。通常制作のデザインは変更しない。
- `tests/easy-state-browser.cjs`：読込済み0加工、分割03.pngでの失敗、一括検査での失敗、原因の保持、再試行、日本語10行、入力イベントなしの値変更、旧モジュール混在と、診断欄がないキャッシュ済みHTMLを模した状態を検証。createImageBitmapを無効にし、ImageによるSafari互換の読込フォールバックを使用。

画像加工・透過・文字合成・残留線除去・ZIP生成のアルゴリズムと保存JSONの形式は変更していません。状態や失敗記録は現在開いている画面内だけで保持し、画像をサーバーへ送信しません。

## テストと制限

Node.js全49件成功。ブラウザ8スイートが成功。新規の状態管理テストに加え、前回の10個＋日本語10行の回帰テストで、01〜10の文字画素、プレビュー、PNG／ZIPの一致と再入力後の更新を確認しました。通常制作、全5種類の枚数と40個＋メイン・タブ、JSON、一括確認、文字デザイン、実09.png・10.pngの上端残留線自動削除も回帰確認しました。テストZIPをPythonで独立デコードする検査も実施しています。

## 公開後の実機確認

このブランチの作成だけでは公開版は更新されません。レビュー・mainへのマージとGitHub Pagesのデプロイ完了後に確認してください。

1. 入力済みセリフをコピーし、必要なら設定JSONを保存してから公開画面を再読込します。JSONに未反映の入力は含まれません。
2. かんたんモードに `版 easy-state-1` が表示されることを確認します。表示されない場合は、今回の画面が読み込まれていません。
3. 40個設定で2列×5段画像1枚と日本語10行を入力し、②を押します。`読込済み1枚 / 採用10個 / 加工済み10個 / 申請40個` と文字入り01〜10を確認します。
4. 失敗した場合は消えずに残るエラー全文と表示URLを確認します。全数不足は警告であり、申請用ZIPは引き続き全40個と目視確認が必要です。
