# 判定不能時の安全な提案と分離した装飾の保護

## 調査と対応範囲

mainは25806cc（PR #17）で、前回の94a2445はまだmainに含まれていません。このブランチは94a2445の変更を保持して追加修正しています。

現在の解析は、元画素・透過マスクから作る特徴とラベル付き見本との照合、および限定的な青い涙の特徴検査です。番号順・ファイル名・乱数による表情認識ではありません。未知の猫など任意のキャラクターの笑顔・怒り・眠気を意味として分類する汎用モデルは未実装です。

無料のブラウザ方式の候補として、画像と言葉を照合するCLIP系モデルとONNX/WASM実行を検討しました。公開メタデータ取得先 https://huggingface.co/api/models/Xenova/clip-vit-base-patch32 は、通常実行と制限外の再試行の両方で403となりました。重み取得・ライセンス条件・実行精度・Safari上のメモリと速度をこの環境で検証できていないため、導入していません。無料モデル一般が不可能と結論したものではありません。現行CSPは外部接続を禁止しており、導入には重みの配布と依存関係の検証も必要です。APIキー・有料APIは不要のままです。

## 実装した改善

- **判定不能の画像へ汎用セリフを自動入力する動作を既定で停止。** 未入力と理由を表示し、表情の手動指定または直接入力を案内します。判定不能画像に「承知したよ」が勝手に入ることを防ぎます。希望する場合だけ「判定できない画像にも汎用候補を入れる」を明示的に選択できます。
- 判定できる画像の表情・ポーズ別候補と、利用者が登録済みのセリフは維持。未入力がある状態では一括承認が失敗し、無条件で文字入り完成画像へ進めません。判定不能があるセットをすべて自動で完成させる要件は未達です。
- **左右反転した見本にも対応。** 閾値は緩めず、元向きと反転の小さい距離で照合し、別ラベルとの僅差は棄却します。元画像を反転・加工する機能ではなく、解析内での比較です。
- 同一の画素特徴へ利用者がラベルを明示訂正した場合、同梱ラベルとの競合で判定不能になるのを防ぎ、利用者の訂正を優先。初回の手動ラベルが必要な端末内の見本記憶は維持します。
- **分離した小さな線の組を装飾・詳細候補として保護。** 境界から離れた小成分の距離と全体の大きさを検査し、動き線・怒りマークなどであり得る近い成分を保護側へ移します。ハートや星の意味認識ではありません。小さな不要物も保護される場合があり、必要時は個別編集で確認します。
- 前回追加した小さな色付き装飾の保護、橙/緑の独立オーバーレイ表示、確定エラーと未確定候補の区別を維持。新たな自動削除は追加しません。従来の上端線除去、文字・白フチ・影の保護、画像・ZIP処理も維持します。

- 実データの09に残る上端線が照合範囲を変えてしまうケースも再現。完成PNGと同じ狭い既存規則に合う線だけを、画素特徴の抽出内で除外します。元画像・元マスクは変更せず、輪郭や装飾を広く削除する処理は追加していません。
