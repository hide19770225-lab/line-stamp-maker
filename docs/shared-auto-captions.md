# 通常・一括制作のセリフ機能共通化

## 調査結果と方式

従来の suggestions.js は手動で選択した表情とローカル辞書を対応させる機能です。画像分類器はありません。入口も加工後の details 内に限られていました。

無料方式の比較は layout-caption-review.md を参照してください。Canvas の画素検査だけでは任意のキャラクターの意味・表情を確定できません。人顔向けモデルを任意のイラストに適用した精度も検証できていません。今回はモデルや外部通信を追加せず、代替として「表情未解析」と明示した日常会話辞書を使います。画像に合った表情の自動推論は未実装です。

## 変更

- 画像を読み込むと、通常・一括のどちらでも共通の自動提案ボタンを表示。
- ボタンを押すと既存分割・透過処理を再利用し、空の番号へ重複のない短い日本語セリフを登録して描画。入力済み・登録済みのセリフを保持。
- 新規セリフは既存の20px余白・自動配置を使用。長い文字の縮小・改行も既存処理を再利用。
- 加工後、番号・画像・セリフの共通一覧を開く。手動表情指定による候補変更、個別修正、重複警告、承認機能を維持。
- 40個設定で10個の部分制作が可能。不足分を汎用セリフだけで埋めたり、申請ZIPの不足検査・目視確認を省略したりしません。
- 既存キャラクターの画素・マスク・分割設定・色は候補割当により変更しません。保存JSON形式は変更しません。

## 制約

汎用候補は表情と一致する保証がありません。一覧で確認し、必要なら表情を選び直して承認してください。自動入力は透過確認の承認ではありません。画像未読込時にはボタンを表示しません。既存セリフを変更したい場合は共通一覧または個別編集を使います。

iPhone実機Safari・ホーム画面追加版は未検証です。ブラウザテストはChromiumのiPhone 13タッチ画面エミュレーションで実施します。

## 今回の検証

- Node自動テスト53件成功。
- 新規ブラウザテスト：通常・一括それぞれ10個。画像読み込み直後の入口、入力済みセリフ保持、全番号の日本語登録、文字なし描画との画素差、透過余白、再実行の画像一致を確認。
- 回帰：提案一覧10/40個、部分制作、処理状態・再試行、20pxレイアウト、一括透過確認を検証。
- 提案一覧回帰が出力した10個＋メイン・タブ、40個＋メイン・タブのZIPを独立したPNGデコーダで検査し、一覧とのRGBA一致、日本語文字描画、サイズ・透明余白・容量・CRCを確認。
- 実機Safariおよび任意キャラクターの表情分類精度は未確認です。今回の新ボタンの40個一括自動入力は純粋関数テストで確認し、40個のブラウザ回帰は既存の表情指定・承認経路で確認しています。
