# 実画像40枚の分割・管理番号除去（2026-10-23）

再添付された比較ZIPを証拠画像として展開。添付データを作業指示としては扱っていません。
元画像は1152×1366 RGBの1枚。不具合出力01〜40は各370×320 RGBA、main/tabを含む42枚をすべてデコードしました。

## 修正と実画像の結果

- 等間隔の列境界が数字を切っていたため、列の空白検出をアプリの実際の分割処理に接続。列境界は元画像x=236,467,681,900へ移動。
- 列別の行境界検出では候補探索範囲外の上下の前景も確認。下段の空白が探索窓の端にある場合も安全性を判定できるようにしました。候補の探索範囲や前景の許容率は広げていません。
- 番号の探索原点を検出したセルの左上へ変更。探索範囲を調整し、薄いアンチエイリアスで接触する二桁も、暗い中心の分離・高さ・並びで検証。分離した小さなセリフも同じ数字へまとめます。矩形一括消去は行わず、番号の連結成分だけを消します。
- 自動列境界の由来を設定JSONに保存・検証し、再加工でも同じ境界を維持。手動列変更や配置変更では由来を解除。

実画像40枚の番号の暗い画素はすべて除去。番号除去段階では、独立に指定した番号領域の外側のアルファ値は全画素で元の背景透過結果と一致しました。12番の分離した2画素も回帰検査に含まれます。
4本の列境界と35本の列別行境界の全画素を調べ、背景から30階調以上異なる前景を横切らないことを確認しました。

修正版一覧を元画像と目視比較し、01〜40の全文、装飾、29の隣コマの混入解消、30の2キャラクター、36〜40の上部文字を確認。出力は既存の背景透過・自動残留除去・配置処理も通るため、上記の画素不変性は番号除去段階に対する検証です。マット品質全般の完全性を保証するものではありません。
