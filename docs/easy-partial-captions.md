# 10個のテスト制作でセリフが反映されない問題

## 原因と再現

申請枚数の初期値は40個です。従来のかんたんモードは、10個入り画像1枚に対して11〜40番が未割当であることを加工開始時のエラーとして扱っていました。この判定がセリフの登録より前にあるため、入力した10行を画像に反映する処理まで到達しませんでした。すでに通常加工した10個の結果がある場合は、古い「（セリフなし）」の一覧・PNGがそのまま残りました。

修正前に、通常加工で10個のセリフなし画像を作り、かんたんモードへ切り替えて日本語10行を入力するブラウザテストを追加しました。実際に全10個が「（セリフなし）」のままで失敗しました。単体テストでも部分制作が不足エラーで停止することを確認しました。今回の再現画像は自動生成したテスト用2列×5段画像です。今回の利用者の元画像・端末を直接再現したものではありません。

## 修正

- `easy.js`：検証に `allowPartial` オプションを追加。加工可能な番号が1個以上ある部分制作では不足だけを警告に変更。0個、画像未選択、番号・画像の重複、不正番号や4枚制限は引き続きエラー。初期値は厳格な検証のままです。
- `app.js`：テスト加工でだけ部分制作を許可。既存のセリフ登録→番号への反映→描画→一覧・一括検査を実行し、10/40個のテスト加工であることを表示。
- `index.html`：更新後のJSが一緒に読み込まれるようキャッシュ識別子を更新。
- `README.md` / `docs/easy-batch-production.md`：部分制作と申請用出力の区別を追記。
- `tests/easy.test.cjs` / `tests/easy-partial-browser.cjs` / `tests/verify_partial_zip.py`：今回の再発防止テスト。

既存の描画・文字自動配置・背景透過・残留線除去・PNG／ZIP生成のアルゴリズムは変更していません。セリフ変更時は既存のセリフ登録が加工済みスタンプも更新し、確認状態を解除して描画し直します。画像の分割を再実行する必要はありません。

## 検証

- Node.js全49件成功（既存47件＋今回2件）。
- 新しいブラウザテストは「すでにセリフなし10個を加工済み」「新規に1枚を読み込み」の両方を検証。
- 10行すべてで番号・一覧のセリフ・描画計画の日本語が一致。完成画像の実際の文字画素を文字レイヤーと照合し、全10個で不一致0。
- さらに10行すべてを別のセリフに変更して再加工し、全画像の画素ハッシュが更新されることを検証。
- 完成画像・通常一覧・一括確認プレビューがRGBAで完全一致。
- PythonでテストZIPの全PNGを独立にデコード。全10画像のRGBAがプレビューと一致し、単独保存の09.pngもZIP内と一致。ファイル名、サイズ、透明余白、容量、PNG・ZIPのCRCを確認。
- 10/40のままでは全数の一括確認と、かんたんモードの申請用ZIPは実行不可。既存の明示的なテストZIP（line-stamps-test-10.zip）は維持。
- 回帰ブラウザテスト：通常制作、全5種類の完成セット、40個＋メイン・タブのZIP、日本語文字デザイン、JSON、個別編集・一括確認、実データ上端残留線の自動削除を確認。

通常制作の回帰テストは、並列実行時に40枚ZIPのダウンロード待ちが1回タイムアウトしました。アプリのコードやテストの制限時間を変更せずに単独再実行し、40枚ZIPを含む全チェックが成功しています。並列時の原因が実行負荷だけであったことまでは確定していません。

実機iPhone Safariとホーム画面からの保存は未確認です。ブラウザ検証はChromiumのiPhone 13タッチ設定です。外部API・画像送信・有料サービスは追加していません。
